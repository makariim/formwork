# Round brief: formwork for building a whole project

Brief 0022. The lead wrote this briefing. It stands in for the repository: you
should not need anybody else's reading list. The full brief is
`docs/briefs/0022-whole-project-builds.md` and the idea is
`docs/ideas/2026-11-15-whole-project-builds.md`. Read both first. They are short.

## Goal

Formwork today runs one loop (brief, work, check, report, stop) very well. The
person who uses it built whole products with it (an iPhone app, a large
assistant product, a research deck, a studio site) and had to supply by hand the
method for a whole product: the phase cycle, the research round shape, taste
rules, user first stories, review rounds on the running product, project
specific roles, usage awareness. He wants a proposal for what formwork becomes so
that it handles a whole project end to end, with roles spawned dynamically.

**The centre of the proposal: understanding from one prompt.** From one plain
request ("build me an iPhone app for X", "fix this bug", "research Y", "make a
deck") the setup works out on its own the kind of work, the layer and phase,
which roles to bring in or create, which templates, checks and hooks apply, and
which briefs to write. It says that plan back in one or two plain lines and runs
it. Where does that understanding live (the user's CLAUDE.md, the project's
AGENTS.md, a formwork router or skill, the director role), how does it stay right
as a project grows, how does a person correct it, and how does it avoid over
building a small ask (a task keeps a one line brief).

## Constraints, in my words, with where they live

1. **Research and proposal only. Nobody edits the kit** (`formwork/`,
   `formwork_cli/`, `FORMWORK.md`). Brief 0022, Rules. Write only your own file
   in this folder.
2. **Formwork is a general repository.** Nothing personal or machine specific
   goes in it: no release machine, accounts, devices. His words: "the mac air
   pipeline btw shouldnt be a persistent thing, remember, formwork itself is a
   general repo". The kit may at most describe a general pattern.
   (Idea file; the user's memory rule "nothing private public".)
3. **Privacy.** You will read other projects. Quote method only. Never personal,
   health, body, or relationship content. Never open `~/Personal/Repos/stride/docs/profile/`.
   Never read `.env`, credential, token or key files.
4. **Evidence.** Every claim about another tool or method carries a source (a URL
   or a file path). Unknown means write NOT ESTABLISHED. A number comes with the
   command that produced it. (`docs/style.md`, `formwork/rules/core.md`.)
5. **The kit's own shape**: one loop, five sizes already named in
   `formwork/loop.md` (task, checkpoint, round, phase, milestone) but only the
   first three have templates. Briefs and reports numbered in pairs. The human
   says go at every STOP. The human writes decisions and the read-back; agents
   never do (`formwork/roles/method/director.md`). Only `lead` may spawn
   (`role-shape` check). Every role has five sections: Owns, Does not own, Tools,
   Stops when, Would be wrong if (`formwork/roles/TEMPLATE.md`). Every rule names a
   check, and every check ships a fixture that breaks it (`FORMWORK.md`).
   No `[roles]` switch exists yet, and the kit says so rather than faking one.
6. **The kit's open question already on record** (`docs/standing.md`, What is
   open): "Whether the `lead` may invent a role ... Open, and it cuts across what
   `role-shape` is for."
7. **Style.** Plain English, short sentences. No em dashes or en dashes anywhere.
   (`docs/style.md`.)

## What already exists in the kit, briefly

- `FORMWORK.md`: the loop, three guards, thirteen checks, 28 roles (7 method, 21
  in packs), 48 rules.
- `formwork/loop.md`: five sizes. "Phase: a question big enough that its answer is
  a document. Milestone: a direction. It contains phases." Nothing more for them.
- `formwork/round.md` and `formwork/templates/`: brief, report, round,
  predictions, decision, standing.
- `formwork/roles/method/director.md` (planning layer, sizes briefs, keeps
  `docs/standing.md`), `lead.md` (rounds and split briefs).
- `formwork/roles/HOW-TO-ADD-A-ROLE.md`: project roles go in a
  project roles folder under formwork roles, generated by `formwork roles`, checked by `role-shape`.
- `formwork/check/checks/`: config-shape, decision-ids, doc-links,
  generated-current, guard-wired, kit-integrity, predictions-first, report-shape,
  role-shape, rule-labels, standing-current, style-pointed, work-paired.
- `formwork/skills/humanizer/`: the first skill the kit ships.
- History: `docs/design.md`, `docs/gap-map.md`, `docs/survey.md` (a survey of
  other agent kits), `docs/dogfood.md`.

## Failures this area already produced

- The director offered to build four times in its first real use
  (`director.md`, What goes wrong).
- Paperwork larger than the work kills the method quietly (`director.md`, Size
  the brief).
- Skills and a model per role were planned and dropped (`docs/standing.md`, What
  we tried and stopped).
- Stride v1 was "correct and dead": clean is not the same as alive (idea file).
