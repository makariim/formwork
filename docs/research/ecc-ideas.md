# ECC: ideas formwork could take

## ECC in twelve lines

ECC is one maintainer's very large plugin for coding agents, MIT licensed,
version 2.2.3. It ships 71 agents, 314 skills, 98 slash commands, 27 hook
entries, 10 common rule files plus 21 language packs, a Rust control plane in
`ecc2/`, and installers for about 15 runtimes, Claude Code first. Its loop is
"plan, test, implement, review, verify, remember, improve" (`README.md`). Most of
it is advice: agents marked "use PROACTIVELY", rules, skills. A small part
refuses: `--no-verify` commits, edits to lint configs, the first edit of each
file until facts are stated, dev servers outside tmux. It also logs every
session, sums cost, writes summaries with a hidden model call, and infers
"instincts" by itself. Its best work is not the catalogue. It is how it measures
its own hooks, including an honest finding that its flagship gate costs about
45% more and showed no gain.

## Contradictions first

1. **The repository could not be cloned the way the job said.** Formwork's own
   `git-boundary` guard refused `git clone` ("not on the read-only list"). The
   copy was taken as a tarball with `curl` from `codeload.github.com` instead,
   into the folder the job named. Nothing from it was run.
2. **ECC calls its hooks "enforcement", but most of them only warn.** Of the hook
   rows in `hooks/README.md`, the blocking ones are the dev server blocker,
   critical findings in the pre-commit check, `config-protection`,
   `block-no-verify`, `mcp-health-check`, GateGuard and Hookify rules set to
   `block`. Everything else writes a reminder. Its validators also default to
   warning: `scripts/ci/validate-skills.js` says frontmatter findings "default
   to WARN so CI does not break".
3. **ECC's own measurement argues against its biggest guard.** GateGuard
   (`scripts/hooks/gateguard-fact-force.js`, 2,750 lines) denies the first edit
   of each file until the agent states facts. Its own study
   (`docs/gateguard/question-effectiveness.md`) found: pilot of 72 sessions, all
   arms 18 of 18, "no information at all", and the gate cost "about 45% more
   turns and 28% more tokens"; then a hidden intent run of 48 trials, $7.14,
   "41% more turns and 45% more cost", mean score slightly lower, and "firing
   does not convert into asking". That is the lesson to take, not the gate.
4. **The tmp path in the brief belongs to another job id** (`86fe1ca4`, this job
   is `ff75943d`). It was used as told, and is deleted at the end.

| Context budget | A "lean" profile: three skills loaded eagerly, the rest routed, an 8,000 token blocking budget. Trigger phrases exist for 34 of 314 skills | `manifests/context-profiles/lean@1.json`, `manifests/context-packs/skill-triggers@1.json` |
| Routing eval | Paraphrased prompts that "avoid the target skill vocabulary"; "anything it loads must be in expected" | `tests/fixtures/context-selection/routing-prompts.json`, `docs/design/context-profile-delivery.tdd.md` |
| Hook evals | A labelled corpus (`expect`, `mustDeny`, `redundant`) replayed against the working tree and older git refs, counting redundant denials and bypasses; then live trials with off, gate, placebo and minus-target arms, hypotheses written before the run | `docs/gateguard/evaluation.md`, `docs/gateguard/question-effectiveness.md` |

| Safety | A long guide (sandboxing, hidden unicode, least agency, kill switches); an external scanner "AgentShield" sold as an npm package | `the-security-guide.md`, `README.md` |

**What it enforces versus suggests.** Enforced, by exit code or a deny
decision: the hooks listed in contradiction 2, Hookify `block` rules, the
install consent stop, the release approval script, and CI validators that
error. Suggested: every agent and its "use PROACTIVELY", every skill, every
rule file, TDD and 80% coverage in `AGENTS.md`, the session summaries, the
instincts, cost and context warnings.

**Network.** The MCP list (`mcp-configs/mcp-servers.json`) names 34 servers,
most of them hosted (jira, firecrawl, supabase, vercel, exa search and so on).
The PreCompact summary spawns `claude -p` (`scripts/lib/llm-summary.js`), which
is a model call the user did not ask for.

## 2. Point by point against formwork's principles

| Principle | Formwork | ECC | Verdict |
|---|---|---|---|
| **One loop** | `BRIEF, WORK, CHECK, REPORT, STOP`, five sizes, one loop (`FORMWORK.md`) | Several loops beside each other: orch pipeline, plan-prd chain, santa loop, GAN loop, loop-operator agent, continuous learning (`commands/`) | Formwork is stronger. ECC's orch pipeline is the nearest match and agrees with formwork's "run alone between two gates" |
| **Checks shown to reject the wrong and accept the right** | Every check ships with a breaking input; `formwork demo` shows each refuse | Unit tests for hooks (`tests/hooks/`), and for GateGuard a full labelled corpus with baselines and placebo arms. Validators warn by default | Formwork is stronger on checks in general. **ECC is stronger on measuring a guard's effect**, and that is the main idea to take |
| **A guard that cannot be talked around** | Three guards, pattern matching, limits written down (`formwork/limits.md`); turn-end gate with a budget | Many switches per hook by env (`ECC_DISABLED_HOOKS`, `ECC_GATEGUARD=off`); Hookify rules fail open on bad config; but fail closed on oversized input, and hard links always gated | Equal in kind. ECC closes one hole formwork lists as open (hard links) |
| **Generic kit, nothing personal** | `kit-leak-scan` over kit files | `validate-no-personal-paths.js` catches only `/Users/<name>` and `C:\Users\<name>`, and exempts `docs/fixes/`. `docs/LANE-RULES.md` names the maintainer's machines and folders ("the ops mini", `~/GitHub/ECC-worktrees`, `/Volumes/Agent-Runtime/workspaces`); `scripts/release-approval-gate.js` carries example URLs with the maintainer's handle | Formwork is clearly stronger. Do not copy ECC's scan |
| **Read-backs in the person's words** | `in my words:` line, checked by `work-paired`; routing corrections transcribed word for word | The opposite: instincts are inferred from observed tool use by a background model, with a confidence number (`skills/continuous-learning-v2/SKILL.md`) | Formwork is stronger. ECC's learning is the thing formwork chose not to be |

## 4. What ECC does worse, so we do not copy it

1. **It describes more than it enforces.** "Enforcement" in the README; warnings
   in practice (contradiction 2). Formwork's "What is blocked" and "What is
   advice" split is the thing to keep.
2. **Validators that warn by default** (`scripts/ci/validate-skills.js`). A check
   that does not refuse is advice with a test file.
3. **Personal details in a public kit** (`docs/LANE-RULES.md`,
   `scripts/release-approval-gate.js`), and a personal path scan that only knows
   one pattern (`scripts/ci/validate-no-personal-paths.js`).
4. **Many loops.** orch, plan-prd, santa, GAN, loop-operator, learning. A
   newcomer cannot tell which one is the process.
5. **Size.** 314 skills and 71 agents, so it ships a "lean" profile to hide most
   of itself (`manifests/context-profiles/lean@1.json`). Formwork's 28 roles
   checked for a unique `owns` is the better bound.
6. **Hidden model calls and hosted services** (PreCompact summary, MCP list).
   The kit must work with the network off.
7. **Inferred memory.** Confidence numbers on behaviour nobody said out loud.
8. **Commercial pull.** A paid app and sponsors sit at the top of the README;
   nothing wrong in that, but its claims are written to sell (star badges,
   counts). Formwork's "Neither has been tried by anybody else yet" is the tone
   to keep.

What ECC does better and formwork should admit: it measures its guards against a
placebo and publishes a null result about its own flagship feature. Formwork has
not yet measured any guard's effect, only that each one fires.

## How this was done

All reading, nothing run from the copy.

```
curl -sSL -o ecc.tar.gz https://codeload.github.com/affaan-m/ecc/tar.gz/HEAD
tar -xzf ecc.tar.gz -C src --no-same-permissions
cat VERSION                                   -> 2.2.3
head LICENSE                                  -> MIT License, Copyright (c) 2026 Affaan Mustafa
ls agents/*.md | wc -l                        -> 71
ls -d skills/*/ | wc -l                       -> 314
ls commands/*.md | wc -l                      -> 98
python3 -I (sum of entries in hooks/hooks.json)   -> 27
ls rules/common/*.md | wc -l                  -> 10
```

`git clone` was refused by `formwork/guard/git-boundary`; the tarball was used
instead. The JSON files were read with `python3 -I` from outside the copy.
The copy was deleted at the end of the job.

## NOT ESTABLISHED

- Whether ECC's hooks improve outcomes. Its own study did not show it.
- Whether any idea above helps formwork. Each needs its own brief and its own
  must-fail fixture or measurement.
- Whether the GateGuard figures are current: ECC itself says those tables are
  "historical aggregates" whose rows are not in the repository.
- ECC's real install base. The README badges are fetched live and were not read.
