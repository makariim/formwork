# Report 0034: the research pack

## For you

Formwork now has a research pack. It sits beside the taste packs and follows the same idea: it guides people and is never a check.

- **`formwork/research/README.md`** is the method for learning by building.
  - It is framed as design science research.
  - It has a question card in twelve parts. Parts 1 to 8 are committed before anything runs, and that commit date is the registration.
  - It sets out a nine step loop from asking to telling someone outside.
  - It has a table of 16 method names worth knowing, with sources.
- **`formwork/research/pitfalls.md`** lists 21 ways this kind of work goes wrong.
  - Each item says what it catches, how it is found, and a public source.
  - They come from one project's months of research, reviewed against lab practice, and are written with no product or person in them.
  - Examples: agreement reported as correctness, a gate with no origin, a registration nobody can date, one run per arm, synthetic data only.
- **Two templates:**
  - `research-question.md`, the card;
  - `evaluation-plan.md`, where each part names the pitfall it guards against.
- **One skill, `research-question`.** It writes the card with the person, checks it against the pitfalls, and never commits for them.
- **The `researcher` role** now points to the pack. The README's kit index lists it.

**The gate is red on one check only, `work-paired`.** Brief 0033 is still open waiting for your read back, and the limit is one open brief. Everything else is green, and all four test files pass.

**One test was changed.** `test_install.py` checked that an install writes exactly the kit's one skill, and the kit now ships two. The expected set now lists both. It is still an exact match, so a stray file still fails it.
